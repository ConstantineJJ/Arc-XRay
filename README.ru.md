<h1 align="center">Arc-XRay</h1>
<p align="center">Независимый анализ архитектуры. Единый интерактивный синий атлас.</p>

[English](README.md) · [Руководство](docs/USAGE.ru.md) · [Ограничения](docs/CAPABILITIES.md)

Arc-XRay — **самостоятельный плагин со Skill и программными ресурсами**.
MCP, коннекторы и API key не нужны. Агент исследует реальные исходники, затем
создаёт интерактивный **index.html**. В Chat, Work и браузере используется один
комплект HTML/CSS/JS и одна полная модель данных.

## Установка через приложение

[Скачайте arc-xray-0.2.0.zip](https://github.com/ConstantineJJ/Arc-XRay/releases/download/v0.2.0/arc-xray-0.2.0.zip): **Plugins → Добавить → Загрузить архив
плагина**. Откройте новый чат и выберите Arc-XRay. В архиве находятся инструкции,
Python-анализатор, шаблон синего UI, локализация и исходный значок.

Страница Skills показывает инструкции агенту — это нормально. Работающий код
находится в дополнительных файлах того же Skill, а не в MCP-сервисе.

При замене 0.1.0 используйте действие замены/обновления, если оно есть в приложении.
Иначе удалите старую установку Arc-XRay и импортируйте новый ZIP. У новой версии
нет регистрации MCP. Кэш вручную не редактируйте; созданные атласы хранятся отдельно.

## Установка в терминале

**Windows PowerShell 5.1 и новее** — две строки без `&&`:

```powershell
codex plugin marketplace add ConstantineJJ/Arc-XRay
if ($LASTEXITCODE -eq 0) { codex plugin add arc-xray@arc-xray }
```

**Git Bash в Windows**:

```bash
codex.exe plugin marketplace add ConstantineJJ/Arc-XRay && codex.exe plugin add arc-xray@arc-xray
```

**Bash в Linux/macOS**:

```bash
codex plugin marketplace add ConstantineJJ/Arc-XRay && codex plugin add arc-xray@arc-xray
```

В репозитории также есть `install.ps1` и `install.sh` с режимом проверки без
установки. Они не меняют другие плагины. Для самого анализа нужны Python 3.10+
в окружении приложения и доступ к исходникам. Установка плагина сама по себе не
открывает доступ к диску и не добавляет Python в обычный Chat.

## Пример запроса

> Используй Arc-XRay. Выполни полный анализ исходников без изменений: архитектура,
> зависимости, данные, выполнение и ревью проблем. Проследи успешный запрос,
> ошибку, повтор или отмену. Дай стандартный синий index.html, просмотр этого же
> файла внутри приложения, отчёт, доказательства и редактируемые схемы.

Первичная автоматическая карта имеет статус «исследование», а не «полный аудит».
Агент должен дочитать исходники, описать модули и закрыть пять областей ревью.
Финальная проверка не пропустит неполную область, пропущенный модуль или
неразобранный путь выполнения. Это контроль записанной полноты, а не доказательство
безошибочности выводов или поведения runtime.

## Возможности

Карта и дерево, zoom/pan, поиск, группы, фильтры и цветные стрелки, описания
компонентов с входами/выходами и исходниками, крупный текст и режим «Только канвас».
Анализ охватывает ошибки, противоречия, избыточность, связанность, возможные проблемы
эффективности и другие риски. Наблюдение отделяется от последствия и предложения.

Логи наблюдений сохраняются по одному или пачкой в Markdown/JSON. При поддержке
браузером доступен Save As; иначе папку определяют настройки загрузки.

Результат: `index.html`, `atlas.json`, `REPORT.md`, `COMPONENTS.md`,
`architecture.drawio` и `flows.md`. Русский/английский UI; исходные имена и
доказательства сохраняются. Для всех способов просмотра используется один UI.

## Рабочий локальный пример

Из корня скачанного репозитория в PowerShell:

```powershell
python .\arc-xray.py audit .\examples\python-service --out .\.test-output\demo --enrichment .\examples\python-review.json --language ru --finalize
Invoke-Item .\.test-output\demo\index.html
```

Это готовый проверяемый пример; менять пути для него не нужно. Для своего проекта
агент подставляет реальные доступные пути. Строки с буквальными `<plugin-root>`
копировать в терминал нельзя — это были обозначения, а не рабочие команды.

## Границы

Обычному Chat нужен доступный исходный проект и окружение, позволяющее читать
ресурсы Skill и выполнять Python. Если их нет, агент должен назвать ограничение,
а не рисовать другую упрощённую карту. Просмотр зависит от HTML preview приложения;
тот же index.html можно открыть отдельно в браузере без сервера и соседних файлов.

Статический анализ не доказывает runtime, безопасность или измеренную эффективность.
Для Python есть AST, для ряда языков — lexical adapters; смысловое ревью выполняет
агент. Динамические и generated-связи покрыты неполностью. Код не запускается и
не исправляется; неизвестное остаётся видимым.
